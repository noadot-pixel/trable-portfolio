PROJECT OVERVIEW

プロジェクト概要

開発背景・目的・チーム構成

💡 開発背景

  • 韓国・日本を中心とした旅行コミュニティサービスを、Servlet/JSP + Oracleというフレームワークに頼らない構成で一から実装
  • 最初はFirebaseを使った反応型モックアップから始まり、実データベース(Oracle/JDBC)への移行を前提に設計

🎯 開発目的

  • MVC2パターンに基づいた保守性の高い構造の実装
  • 会員権限・多言語・地図連動統計など、実務水準の機能設計能力の証明
  • チーム開発経験と、個人での継続的なサービス拡張能力の両方を提示

👥 チーム構成(4名)

画面担当/バックエンド担当という役割分担ではなく、各メンバーが特定の機能ドメインを選び、JSP〜Controller〜Command〜DAO〜DTOまでを一人で一貫して実装し、最後にチームで統合する方式を採用。

📅 開発期間 / 技術環境

  • Java 17, Tomcat, Oracle 11g XE
  • Cloudflare Tunnel経由で本番公開(常時稼働)

TROUBLESHOOTING

トラブルシューティング

開発・運用中に実際に遭遇した問題と解決

CDNキャッシュにより、CSS/画像修正が本番に反映されない

問題: CloudflareのエッジキャッシュがCSS/SVG画像を最大4時間キャッシュし、修正してもすぐには反映されなかった。

解決: ファイルの最終更新時刻を取得し、?v=<timestamp>をクエリ文字列として付与。更新するたびにURL自体が変わるため、キャッシュを確実に無効化。

地図をドラッグすると、モバイルでページスクロールができなくなる

問題: ズーム/パン機能のためにtouch-action:noneを設定したところ、地図上での縦方向スワイプが全てパン操作に吸収され、ページスクロールが一切できなくなった。

解決: 拡大していない状態、またはパンがすでに端まで達している状態を検知し、その分の操作をwindow.scrollBy()でページスクロールに回す処理を追加。さらに、サイト全体に設定されていたscroll-behavior:smoothがスクロール命令を毎回アニメーションさせてしまい連続操作が打ち消し合っていたため、behavior:"instant"を明示して解決。

モバイル幅→PC幅にリサイズすると、ヘッダーメニュー全体が反応しなくなる

問題: モバイル幅でドロワーメニューを一度も開かずにPC幅までウィンドウを広げると、閉じた状態のままinert属性がtrueで残り、見た目は通常のPCメニューなのにクリック・フォーカスが一切効かなくなっていた。

解決: リサイズのたびに開閉状態を無条件に再計算するよう修正し、双方向の画面幅変化に対応。

sqlplus経由の韓国語データ投入でUTF-8が化ける

問題: NLS_LANGを明示せずにsqlplusへ韓国語文字列を流し込むと、DB自体はAL32UTF8で正しく設定されているにもかかわらず、投入データだけが文字化け(U+FFFD)した。

解決: NLS_LANG=AMERICAN_AMERICA.AL32UTF8を明示してから実行するよう徹底。

TEAM COLLABORATION & AI USAGE

チーム協業方式とAI活用について

正直に、具体的に示す

✅ 自分が実装した範囲

チームプロジェクト: お知らせ・FAQ・お問い合わせ(JSP〜DTOまで一貫実装)

個人開発(ポートフォリオ化): 多言語対応・ダークモード・管理者権限レベル・インタラクティブランキング地図・モバイル対応 等、全体の高度化を自ら設計・実装

👥 チームでの協業

4名のチームで、機能ドメインごとに各自が担当範囲を一貫実装し、最終的に統合。

アイデアの検討段階ではチームメンバーともフィードバックを交わしながら方向性を発展させた。

🤖 AI活用について(正直に)

個人開発パートの実装では、AIコーディングツール(Claude Code)を積極的に活用した。 特に、SVGベースのインタラクティブな地図やviewBox座標変換のように、カリキュラムでは扱わなかった技術については、 AIから概念と実装の原理を教わりながら学習を重ね、自ら適用した。

AIに代わりに作ってもらった成果物ではなく、AIを通じて技術を教わり、学習を並行しながら完成させた成果物である点を明確にしておきたい。 実装の意図・設計判断・デバッグは自ら行い、AIは「新しい技術を学ぶ相手」として活用した。

📦 プロジェクトの変遷

本プロジェクトは、まずFirebase(Authentication / Firestore / Storage)を用いた反応型モックアップとして チーム4名で共同開発を開始し、その後Oracle/JDBCへの本格移行を行った。 初期モックアップは こちら(チーム初期プロトタイプ) から確認できる。
